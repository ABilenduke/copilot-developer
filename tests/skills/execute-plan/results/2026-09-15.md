## Packaging and limitations

Skill validation passed. Invocation YAML parsed with implicit selection enabled and an explicit
`$execute-plan` prompt. Local reference links resolve; the fictional example's plan link is intentionally
illustrative. Scoped Git and Prettier exceptions include all skill references. The new skill and
evaluation README pass Prettier; `git diff --check` passes. The original Claude executor and companion
agent have no changes.

Repository-wide `npm run format` still fails on 51 existing files outside this change; see
captured output (local artifact: `repository-format.json`). Those files were left untouched. No product build or test
suite applies to this documentation skill; executable verification covers the fixture driver and actual
fixture behavior.

The nine-case probes used separate evaluating workers per variant but shared conversation context
within each worker and inherited the parent conversation. They were instructed not to read the oracle,
other variants, or the replacement before baseline capture; this is not a blinded study. The fresh CLI
run supplies stronger independent evidence for discovery and execution. Cases are deliberately small
Python implementations; larger systems, migrations, and external authorization deserve future trials.

Native Plan Mode was exercised as a read-only scenario constraint, not through the actual Plan Mode UI.
Implicit selection and unrelated-request exclusion were reviewed in metadata/instructions, not measured
with a native-client routing suite. The fresh client used explicit invocation. These limits are preserved
instead of reporting scenario checks as client integration coverage.
